# 关键词封面图片池设计

## 目标

`/home/image`、`/vod/{text}` 与 `/home/imagekey` 继续兼容原 URL。把规范化后的关键词及其尺寸、背景范围、输出格式作为缓存作用域，首次请求同步生成一张并立即返回，后台默认补齐到 10 张。之后从本地磁盘池随机读取，避免重复实时生图。

## 约定

- 后台可配置每池目标数量，默认 10，允许 1–100；保存即对本机生效，其他实例最多 30 秒同步。
- 增大数量后由后续访问补齐；减小数量不删除旧文件。
- 缓存键必须包含关键词、宽高、背景文件名/自动背景范围、JPEG/WebP 格式，禁止不同尺寸或格式串图。
- 自动背景的每个变体独立随机选背景，因此同一关键词的成品图可以不同。
- 目录使用 SHA-256，不把关键词直接用作文件名。目录中保存 `meta.json`，记录原始规范化关键词、尺寸、背景范围、格式和创建时间，满足关键词留档与排查。
- 文件以临时文件加原子重命名写入，随机读取时检查格式；损坏文件重新生成。
- 首次生成及每个后台变体均复用 `Home` 的图片并发槽，后台任务另有独立 worker 数（默认 2），有界队列防止关键词风暴制造无限 goroutine。
- 同一池只允许一个在途补齐任务；客户端断开不取消后台补齐，服务停止时等待已开始任务退出。
- 缓存未开启或图片池 nil 时保留现有直接生成逻辑，便于测试及故障降级。

## HTTP 与 Cloudflare

成功封面响应：`Cache-Control: public, max-age=86400, s-maxage=2592000`、`Cloudflare-CDN-Cache-Control: public, max-age=2592000`、`Vary: Accept`。CF 命中期间固定返回该边缘节点已缓存图片；回源后才重新随机。错误和 503 一律 `no-store`，不得被缓存。

## 后台

复用登录会话及 Mongo 控制面。新增 `GET/PUT /api/cover-pool`，请求/响应配置为 `{"count":10,"sizes":["600x800",...]}`。新增“封面图片池”后台页面：数量与尺寸白名单配置；支持手工粘贴关键词，经 `POST /api/cover-pool/generate` 按白名单多尺寸、固定 WebP 入队补齐备用图（不做清缓存）。

## 验收

1. 先写失败测试，再实现图片池隔离、随机读取、补齐去重、数量边界与持久化。
2. 验证首次请求只同步生成一张、最终达到配置数量、不同尺寸和格式不串图、重启可复用。
3. 验证 CF 缓存头、认证与输入校验。
4. `go test ./...`、`go vet ./...`、构建和端到端 HTTP 验证通过。
5. 先为 v99 当前镜像打回退 tag，发布后验证服务、时区、日志与实际图片池，再提交和推送。
